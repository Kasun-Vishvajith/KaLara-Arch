# Step 17 — Templates, settings, and first-run workflow

## Objective

Make starting and returning to a project effortless.

## Entry gate

Step 16 passed, or all its requirements verified in the baseline audit. Read AGENTS.md and docs/PROGRESS.md. Inspect actual source, Git status, relevant prior evidence, and the linked contracts before modifying code.

## Required reading

- [docs/12_PROJECTS_AND_RECOVERY.md](../../docs/12_PROJECTS_AND_RECOVERY.md)
- [docs/06_UI_AND_VISUAL_DESIGN.md](../../docs/06_UI_AND_VISUAL_DESIGN.md)

## Work package

Empty/template start; known/undecided wizard; local editable seeds; recent files; project/user settings split; context help and command search; default presets.

Implement all listed tasks through the approved layer boundaries. Keep the application buildable; wire visible actions to functioning commands and record incomplete internal work explicitly while the step remains active.

## Acceptance evidence

Empty path works with minimal input; template creates editable entities in one transaction; unknown fields remain unknown; recent missing files handled clearly.

Record actual command lines, platform/build version, test results, numerical outputs, fixture IDs/hashes, and relevant UI screenshots in docs/evidence/STEP_17.md. Use fixed expected values from domain contracts. Distinguish PASS, FAIL, and NOT RUN.

## Scope guard

No questionnaire that blocks Empty or online template dependency.

## Failure handling and handoff

If a mandatory criterion fails, reproduce and fix it before advancing. If access prevents verification, leave this step BLOCKED with the precise missing environment/action; do not report it passed from code inspection. Update docs/PROGRESS.md with implemented versus remaining tasks, changes, risks, and next action. Commit focused changes under authorization. Continue to the next step only after this gate passes, unless the user's chosen review mode requires a pause.
